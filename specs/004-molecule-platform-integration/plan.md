# Implementation Plan: Molecule Platform Integration

**Branch**: `004-molecule-platform-integration` | **Date**: 2026-01-28 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/004-molecule-platform-integration/spec.md`

## Summary

Integrate the DK Molecule Data Platform (107k lines across 274 files on the `Philipp-working` branch) into the dk-alchemy-aligned staging environment via selective code checkout — bringing application code, SQL migrations, SQLMesh models, and documentation while excluding conflicting infrastructure files. Create new Kubernetes CronJob manifests, extend the database init job, update PostgREST configuration, and wire molecule API routes into the existing FastAPI application.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: FastAPI, psycopg2-binary, httpx (new), pyjwt (new), SQLMesh, Pydantic, structlog, OpenTelemetry, prometheus-client, kubernetes
**Storage**: PostgreSQL 16+ via PostgREST v12.x, 12 schemas (6 existing + 6 new molecule schemas)
**Testing**: ruff (lint), kustomize build (manifest validation), docker build (image validation)
**Target Platform**: Kubernetes (dk-alchemy K3s cluster), ArgoCD app-of-apps, Doppler secrets
**Project Type**: Single backend data platform (monolithic Python package)
**Performance Goals**: Pipeline jobs complete within 4h; PostgREST queries sub-second
**Constraints**: Single container image, internal-only FastAPI, selective merge (no git merge), entity resolution threshold 0.80, core 5 sources for initial staging
**Scale/Scope**: 5 core data sources (ClinicalTrials.gov, OpenFDA Labels, OpenFDA FAERS, ChEMBL, PubChem), 500K+ molecules (silver layer), 1M+ bronze records

## Key Technical Decisions

| Decision | Choice | Reference |
|----------|--------|-----------|
| Merge strategy | Selective `git checkout` per path | research.md D1 |
| Schema naming | `mol_` prefix for all molecule schemas | research.md D2 |

## Risk Register

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| Import breakage after selective checkout | High | High | Copy in dependency order; run `ruff check` incrementally |
| Missing Python dependencies | Medium | Medium | Diff pyproject.toml between branches; `uv lock` validates |
| SQLMesh config has hardcoded credentials | High | High | Update to read from env vars; add to `.env.example` |
| Circular imports in service modules | Medium | Medium | Review import graph; use lazy imports |
| API route registration breaks existing endpoints | Low | High | try/except pattern; `/health` smoke test |
| CronJob resource limits too low for transform | Low | Medium | Monitor in staging; adjust via overlay patches |
