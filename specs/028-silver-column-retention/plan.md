# Implementation Plan: Silver Column Retention

**Branch**: `028-silver-column-retention` | **Date**: 2026-04-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/028-silver-column-retention/spec.md`

## Summary

95 silver SQLMesh models are dropping domain columns from their upstream bronze sources. Since external apps only read silver/gold, these dropped columns are invisible to consumers. Fix: audit each silver model SQL against its bronze upstream(s) and add all missing domain columns to the SELECT statement. Excludes system/ETL columns (`raw_json`, `raw_source_id`, `processed_to_bronze`, `processed_to_silver`, `_bronze_loaded_at`).

## Technical Context

**Language/Version**: SQL (PostgreSQL 16.4 dialect) for SQLMesh models, Python 3.11+ for tooling  
**Primary Dependencies**: SQLMesh >=0.90, PostgreSQL 16.4 via CloudNativePG  
**Storage**: PostgreSQL — silver schemas (`mol_silver`, `hcs_silver`, `ind_silver`)  
**Testing**: `sqlmesh plan --dry-run` for model compilation, column-diff audit script for verification  
**Target Platform**: K3s cluster (dk-data-prod namespace)  
**Project Type**: Single (data platform)  
**Performance Goals**: Silver transforms complete within existing CronJob deadlines (no regression)  
**Constraints**: Additive changes only — no existing columns removed or renamed. JSONB columns preserved as-is.  
**Scale/Scope**: 95 silver SQL models across 3 schemas, ~53 upstream bronze models

## Phase 0: Research

No unknowns to resolve. The technical approach is straightforward:
1. For each silver model, read its SQL to identify the upstream bronze source(s)
2. Read the bronze model SQL to get the full column list
3. Diff against the silver SELECT columns
4. Add missing domain columns to the silver SELECT

### Excluded Columns (system/ETL — do NOT carry to silver)

- `raw_json` / `raw_source_id` — raw API response blob
- `processed_to_bronze` / `processed_to_silver` — ETL processing flags
- `_bronze_loaded_at` — internal timestamp
- `id` (bronze-generated surrogate key — silver generates its own)
- `created_at` from bronze (silver has its own `created_at`)

### Column Collision Rules

When a silver model joins multiple bronze sources and column names collide:
- Prefix with source name: `chembl_max_phase`, `drugbank_max_phase`
- If one source is the "primary" and others enrich, the primary keeps unprefixed names

### JSONB Handling

JSONB columns (arrays, nested objects) are carried as-is. No flattening, no type conversion.

## Phase 1: Design

### Approach: Batch Modification by Domain

Split the 95 silver models into 3 work batches by domain:

**Batch 1: mol_silver (67 models)** — Largest batch. Includes high-impact models: drugbank, adverse_events, molecules, fda_drugs. Many single-source pass-throughs that just need missing columns added.

**Batch 2: hcs_silver (26 models)** — CMS healthcare models. Includes the multi-source aggregation model cms_facility_profile. Most are single-source bronze→silver with entity linkage.

**Batch 3: ind_silver (2 models)** — Indication domain. Small, likely minimal gaps.

### Model Categories

Each silver model falls into one of these patterns:

**Pattern A: Single-source pass-through (estimated ~60 models)**
Bronze has N columns → Silver should have N columns + entity-resolution columns (molecule_id, etc.)
Fix: Add missing columns to SELECT.

**Pattern B: Single-source with derived columns (~20 models)**
Silver adds computed/derived columns (CASE expressions, string manipulations) on top of bronze.
Fix: Add missing source columns to SELECT alongside existing derived columns.

**Pattern C: Multi-source join/aggregation (~10 models)**
Silver joins 2+ bronze tables. May have column name collisions.
Fix: Add missing columns with source prefix where needed. Keep existing aggregation logic.

**Pattern D: Already complete (~5 models)**
All bronze columns already present (e.g., clinical_trials, drug_labels).
Fix: None needed — verify only.

### Verification Script

After all models are modified, run a column-diff audit:
```sql
-- For each silver model, compare columns against upstream bronze
-- Output: silver_model, bronze_source, missing_columns[]
```

This can be run via `sqlmesh plan --dry-run` to verify compilation, plus a custom Python script that parses the SQL ASTs to verify column coverage.

### Data Model

No new entities. Existing silver tables gain additional columns. No schema migrations needed — SQLMesh handles physical table changes via its plan/apply mechanism.

### Contracts

No API contracts — this is an internal data layer change. PostgREST views that expose silver tables will automatically surface the new columns.
