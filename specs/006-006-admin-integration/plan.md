## Summary

Fix critical production issues preventing Admin App Compass features from working with dk-data PostgREST API. The primary issue is db-init job failing in production due to PL/pgSQL `DO $$...$$` block escaping within bash heredocs, resulting in 0 Relations loaded and CrashLoopBackOff pods. Secondary work includes adding missing Compass API views (`api.molecules`, `api.resolution_queue`) and implementing graceful degradation patterns for Admin App resilience.

## Implementation Phases

### Phase A: Production db-init Fix (P0)

**Goal**: Fix heredoc escaping so db-init job creates roles and views without SQL errors.

**A.1 Diagnose Escaping Issue**
1. The current db-init uses `<<'SQL'` heredocs containing `DO $$ ... $$` PL/pgSQL blocks
2. When executed through Kubernetes Job, shell layers mangle the `$$` delimiters
3. Production logs show: `ERROR: syntax error at or near "$"` at `DO $`

**A.2 Fix Strategy: Individual psql -c Commands**
1. Replace heredoc `DO $$ ... $$` blocks with individual `psql -c` commands
2. Use proper escaping: `\$\$` in bash strings
3. Alternative: Use different dollar-quote tags like `$role$` or `$init$`

**A.3 Apply Fix**
1. Update `k8s/base/db-init-job.yaml`:
   - Role creation section: Convert to `psql -c "DO \$\$ ... \$\$;"`
   - Permission grant sections: Convert dynamic EXECUTE blocks
   - Cross-database isolation: Convert or remove (low priority)
2. Test locally in docker container before deployment

### Phase B: Production Pod Recovery (P0)

**Goal**: Recover CrashLoopBackOff pods after db-init succeeds.

**B.1 Trigger db-init in Production**
1. Delete existing failed Job: `kubectl delete job db-init -n dk-data-prod`
2. Apply fixed manifests: `kubectl apply -k k8s/overlays/prod`
3. Verify Job completes with exit code 0

**B.2 Verify PostgREST Recovery**
1. Check PostgREST logs for "Schema cache loaded N Relations" where N >= 5
2. Verify HTTP health probe succeeds: `curl /health` returns 200
3. Delete CrashLoopBackOff pod if it doesn't auto-recover

### Phase C: Add Compass API Views (P2)

**Goal**: Create views expected by Admin App Compass features.

**C.1 Create api.molecules View**
1. Add view definition to db-init-job.yaml:
   ```sql
   CREATE OR REPLACE VIEW api.molecules AS
   SELECT
     id, smiles, inchi_key, name, molecular_weight,
     created_at, updated_at
   FROM mol_gold.molecules
   WHERE is_active = true;
   ```
2. If `mol_gold.molecules` doesn't exist yet, create placeholder view

**C.2 Create api.resolution_queue View**
1. Add view definition:
   ```sql
   CREATE OR REPLACE VIEW api.resolution_queue AS
   SELECT
     id, source_id, target_smiles, status, priority,
     created_at, resolved_at
   FROM mol_app.resolution_queue
   WHERE status != 'completed';
   ```
2. If `mol_app.resolution_queue` doesn't exist, create placeholder

**C.3 Update api.data_sources View**
1. Replace placeholder view with real data if underlying table exists
2. Grant appropriate permissions (web_anon can read, analyst full access)

**C.4 Grant Permissions**
1. web_anon: SELECT on api.molecules, api.data_sources (public views)
2. analyst, api_user: SELECT on api.resolution_queue (restricted)
3. Revoke resolution_queue from web_anon explicitly

### Phase D: Admin App Graceful Degradation (P3)

**Goal**: Improve Admin App resilience when dk-data is unavailable.

**D.1 PostgREST Client Enhancement**
1. Add health check with 30-second cache
2. Return structured unavailable response instead of throwing 503
3. Add `isAvailable()` method for pre-flight checks

**D.2 Service Status Component**
1. Create `CompassServiceStatus` React component
2. Display badge: "dk-data: online/offline/checking"
3. Poll health endpoint every 30 seconds

**D.3 Health Proxy Endpoint**
1. Create `/api/compass/health` route in Admin App
2. Proxy to dk-data `/health` endpoint
3. Handle connection errors gracefully

**Note**: Phase D changes are in Admin App repo, not dk-data-fe. Document patterns but defer implementation to Admin App team.

## Risk Register

| Risk | Impact | Mitigation |
|------|--------|------------|
| Escaping fix introduces new SQL errors | Continued production outage | Test in staging first; use local docker test |
| Compass views depend on non-existent tables | Views fail to create | Use placeholder views with WHERE false pattern |
| Admin App changes require separate deployment | Delayed user-facing fix | Prioritize dk-data fix first; Admin App can follow |
| db-init job runs during active connections | Brief API disruption | Schedule during low-traffic window; changes are additive |
