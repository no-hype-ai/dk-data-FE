# Implementation Plan: dk-alchemy Cluster Deployment

**Branch**: `003-alchemy-cluster-deploy` | **Date**: 2026-01-28 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-alchemy-cluster-deploy/spec.md`

## Summary

Deploy dk-data-fe to the dk-alchemy Kubernetes cluster under `data.behaviorlabs.ai` (production) and `data.preview.behaviorlabs.ai` (staging). This requires restructuring the GitOps manifests to match dk-alchemy's app-of-apps pattern, integrating with the shared CNPG PostgreSQL cluster, Doppler secret management, Traefik ingress, and the LGTM observability stack. Cross-app data access is enabled via NetworkPolicy allowlists and internal Kubernetes service DNS.

The work spans two repositories (dk-data-fe and dk-alchemy) and covers: manifest consolidation, ArgoCD bootstrap integration, Ingress replacement, database initialization, Docker image builds, and observability endpoint corrections.

## Technical Context

**Language/Version**: Python 3.11+ (Job Trigger FastAPI service), SQL (PostgreSQL 16.4), YAML (Kubernetes manifests)
**Primary Dependencies**: PostgREST v12.2.3, FastAPI, uvicorn, psycopg2-binary, opentelemetry-*, structlog, prometheus-client, kubernetes client
**Storage**: Shared CloudNativePG PostgreSQL 16.4 cluster (`postgresql.infra.svc.cluster.local:5432`), dedicated `dk_data` database
**Testing**: Manual cluster validation (curl, kubectl), ArgoCD sync status, Grafana queries
**Target Platform**: K3s Kubernetes cluster on Proxmox (dk-alchemy), single-node Stage 0
**Project Type**: Infrastructure/GitOps deployment (Kustomize manifests + ArgoCD)
**Performance Goals**: <2s API response time, 100 req/min rate limit, 3 PostgREST replicas for HA
**Constraints**: Single-node K3s, shared CNPG cluster, Doppler-only secret management, Traefik ingress (no nginx)
**Scale/Scope**: 2 environments (prod/staging), ~20 Kubernetes resources per environment, 2 services + 2 CronJobs

## Implementation Phases

### Phase A: Manifest Consolidation & GitOps Restructure (dk-data-fe)

**Goal**: Single source of truth for all Kubernetes resources in `k8s/`, ArgoCD definitions in `.gitops/`.

1. Create `k8s/base/` directory structure
2. Migrate manifests from `.gitops/base/` to `k8s/base/`:
   - `postgrest/deployment.yaml`, `service.yaml`, `configmap.yaml`
   - `ingestion/job-trigger-deployment.yaml` (includes SA, Role, RoleBinding)
   - `ingestion/job-trigger-service.yaml` (extract from current deployment file)
   - `secrets/doppler-secret.yaml` → `doppler-secret.yaml`
   - `observability/service-monitor.yaml` → `service-monitor.yaml`
   - `observability/alert-rules.yaml` → `alert-rules.yaml`
3. Migrate CronJob manifests to `k8s/base/ingestion/`
4. Create `k8s/base/kustomization.yaml` listing all resources
5. Create `k8s/overlays/prod/kustomization.yaml` (from `.gitops/overlays/prod/`)
6. Create `k8s/overlays/staging/kustomization.yaml` (from `.gitops/overlays/staging/`)
7. Fix namespace references: `tavr-data` → removed (namespace set by overlay)
8. Remove `namePrefix` from overlays (dk-alchemy apps don't use namePrefix)
9. Remove `.gitops/base/`, `.gitops/overlays/`, `k8s/postgrest/`
10. Create `.gitops/prod/apps/` and `.gitops/staging/apps/` with ArgoCD resources

### Phase B: Ingress, NetworkPolicy & Rate Limiting

**Goal**: Public PostgREST at `data.behaviorlabs.ai`, zero-trust networking, rate limiting.

1. Create `k8s/base/ingress.yaml` — standard Kubernetes Ingress with Traefik annotations
   - Host: `data.behaviorlabs.ai` (patched in staging overlay to `data.preview.behaviorlabs.ai`)
   - TLS via cert-manager annotation
   - Only PostgREST backend (no Job Trigger paths)
2. Create `k8s/base/middleware-rate-limit.yaml` — Traefik Middleware CRD for 100 req/min
3. Reference middleware via Ingress annotation: `traefik.ingress.kubernetes.io/router.middlewares`
4. Create `k8s/base/networkpolicy.yaml` — default deny + allowlist
   - Ingress: `kube-system`, `infra`, `behaviorlabs-*`, `agentmesh-*`
   - Egress: DNS, PostgreSQL, Alloy OTLP, external HTTPS (for CronJobs)
5. Remove `k8s/postgrest/base/ingress-route.yaml` and Traefik middleware CRDs (replaced by standard Ingress)

### Phase C: Database Integration & Initialization

**Goal**: Dedicated `dk_data` database in shared CNPG cluster, bootstrapped by K8s Job.

1. Create `k8s/base/db-init-job.yaml` — Kubernetes Job with:
   - Image: `postgres:16.4` (CNPG base image)
   - SQL script creating database, schemas, roles, permissions
   - ArgoCD sync wave annotation: `argocd.argoproj.io/sync-wave: "-1"` (runs before deployments)
   - Idempotent: `CREATE DATABASE IF NOT EXISTS`, `DO $$ ... IF NOT EXISTS ... $$`
   - Mounts SQL from ConfigMap or inline
2. Create SQL init script consolidating:
   - Database creation: `dk_data`
   - Schema creation: `raw`, `staging`, `mart`, `scoring`, `meta`, `api`
   - Role creation: `authenticator` (LOGIN, NOINHERIT), `web_anon`, `analyst`, `api_user`, `readonly`
   - Permission grants from existing `002_role_restrictions.sql`
   - Cross-database isolation: `REVOKE CONNECT ON DATABASE behavior_labs FROM authenticator, readonly`
3. Update Doppler secret references:
   - Change `project: dk-infrastructure` → `project: dk-data`
   - Change `config: prod` → `config: prd`
   - Change token secret name to `doppler-token-secret` (dk-alchemy convention)

### Phase D: Observability Fixes

**Goal**: Telemetry flows to shared LGTM stack via correct endpoints.

1. Fix `src/dk_data/observability/__init__.py`: default OTLP endpoint from `alloy.monitoring:4317` to `alloy.infra.svc.cluster.local:4317`
2. Fix `k8s/base/ingestion/job-trigger-deployment.yaml`: `OTEL_EXPORTER_OTLP_ENDPOINT` env var
3. Update ServiceMonitor namespace selectors from `dk-data-fe-prod`/`dk-data-fe-staging` to `dk-data-prod`/`dk-data-staging`
4. Verify alert rules use correct namespace labels

### Phase E: Docker Image & CI Pipeline

**Goal**: Automated container builds for Job Trigger service.

1. Create `Dockerfile` at repository root:
   - Base: `python:3.11-slim`
   - Install: psycopg2 build deps, then pip install from pyproject.toml
   - Copy: `src/dk_data/` package
   - Entry: `uvicorn dk_data.ingestion.batch.api:app --host 0.0.0.0 --port 8000`
   - Non-root user, read-only filesystem compatible
2. Create `.github/workflows/build-push.yaml`:
   - Trigger: push to `main` or `staging`
   - Build and push to `ghcr.io/data-kinetic-projects/dk-data-fe/job-trigger`
   - Tags: `<branch>-<sha7>`, `latest` for main
3. Update `k8s/base/ingestion/job-trigger-deployment.yaml`:
   - Image: `ghcr.io/data-kinetic-projects/dk-data-fe/job-trigger:latest`
   - Add `imagePullSecrets` referencing GHCR credentials
4. Update CronJob manifests to use same GHCR image

### Phase F: dk-alchemy Integration (External Repository)

**Goal**: Bootstrap dk-data-fe into the dk-alchemy app-of-apps.

1. Create `.gitops/external/dk-data-fe.yaml` in dk-alchemy:
   - Bootstrap Applications for prod (main branch) and staging (staging branch)
   - Labels: `tenant: dk-data`, `environment: production/staging`
2. Create `.gitops/repositories/dk-data-bootstrap-project.yaml` in dk-alchemy:
   - Minimal AppProject (ArgoCD resources only)
3. Update `.gitops/external/kustomization.yaml` — add dk-data-fe.yaml
4. Update `.gitops/repositories/kustomization.yaml` — add bootstrap project
5. Update `k8s/infrastructure/postgres/base/networkpolicy.yaml`:
   - Add `dk-data-prod` and `dk-data-staging` to ingress allowlist on port 5432

### Phase G: Branch & Deployment

**Goal**: Staging branch exists, both environments deploy successfully.

1. Create `staging` branch from `main` after all changes are merged
2. Verify ArgoCD detects and syncs both bootstrap Applications
3. Verify database init Job completes successfully
4. Verify PostgREST and Job Trigger pods are healthy
5. Verify `https://data.preview.behaviorlabs.ai` and `https://data.behaviorlabs.ai` respond
6. Verify cross-app access from BehaviorLabs namespace
7. Verify observability (logs in Loki, metrics in Mimir)

## Risk Register

| Risk | Impact | Mitigation |
|------|--------|------------|
| Database init Job fails on shared CNPG cluster | Blocks all deployment | Job is idempotent; can be re-run. Test SQL locally first via docker-compose. |
| ArgoCD sync loop due to manifest drift | Continuous re-deploys | Use `ignoreDifferences` for operator-managed fields. Test with `argocd app diff` before merge. |
| NetworkPolicy blocks legitimate traffic | Service outage | Deploy with `WARN` mode first (log-only) if supported; otherwise test each namespace pair manually. |
| GHCR image pull fails | Job Trigger pods ImagePullBackOff | Verify imagePullSecrets; test pull manually with `docker pull` on a cluster node. |
| Doppler token secret not provisioned | All pods fail to start | Document as prerequisite; add readiness check in quickstart. Token provisioning is manual. |
| cert-manager DNS-01 challenge fails | No TLS certificate; Ingress serves 503 | dk-alchemy already has working cert-manager + Route53. Test with staging Ingress first. |
