## Implementation Phases

### Phase A: Security Hardening (P0 - GitHub #3, #4)

**Goal**: Enforce secure JWT authentication and restrict anonymous access.

**A.1 JWT Secret Validation**
1. Update `k8s/base/postgrest/deployment.yaml`:
   - Add init container to validate `PGRST_JWT_SECRET` is set and ≥256 bits
   - Fail pod startup if JWT secret is empty or weak
   - Add environment variable for minimum secret length validation
2. Document JWT secret requirements in Doppler configuration

**A.2 Anonymous Role Restriction**
1. Update `k8s/base/db-init-job.yaml`:
   - Revoke all default grants from `web_anon`
   - Grant `web_anon` access ONLY to `api.health` and `api.data_catalog` views
   - Remove blanket `GRANT SELECT ON ALL TABLES` for `web_anon`
2. Create explicit allowlist of public views in db-init SQL

**A.3 Role-Based Access Hardening**
1. Ensure `analyst` role has read access to `api.targets`, `api.scoring` only
2. Ensure `api_user` role has appropriate scoped access
3. Add `REVOKE` statements before `GRANT` to ensure clean permission state

### Phase B: Database Initialization Fix (P0 - GitHub #56)

**Goal**: Fix SQL syntax errors and ensure idempotent role creation.

**B.1 Fix PL/pgSQL Heredoc Escaping**
1. Update `k8s/base/db-init-job.yaml`:
   - Replace `<<'SQL'` with proper heredoc escaping for `DO $$...$$` blocks
   - Use single-quoted heredocs consistently
   - Test locally with docker-compose before deployment

**B.2 Role Creation Order**
1. Ensure roles are created in correct dependency order:
   - First: `authenticator`, `web_anon`, `analyst`, `api_user`, `readonly`
   - Then: Grant role hierarchy
   - Finally: Grant schema permissions
2. Wrap all role creation in proper `DO $$ ... $$` blocks

**B.3 Idempotency Verification**
1. Add verification step at end of db-init:
   - Query `pg_roles` to verify all roles exist
   - Query `pg_namespace` to verify all schemas exist
   - Log success/failure explicitly

### Phase C: API Schema Creation (P1 - GitHub #60)

**Goal**: Expose data views through PostgREST.

**C.1 Health Check View**
1. Create `api.health` view in db-init-job.yaml:
   ```sql
   CREATE OR REPLACE VIEW api.health AS
   SELECT 'ok' AS status, now() AS timestamp;
   ```
2. Grant `web_anon` SELECT on `api.health`

**C.2 Data Catalog View**
1. Create `api.data_catalog` view showing:
   - Available data sources
   - Last updated timestamps
   - Row counts
2. Grant `web_anon` SELECT on `api.data_catalog`

**C.3 Core API Views**
1. Create placeholder views for:
   - `api.targets` (hospital targeting data)
   - `api.scoring` (scoring details)
   - `api.data_sources` (source metadata)
2. These may be empty views initially if underlying tables don't exist

### Phase D: Health Endpoints (P1 - GitHub #58)

**Goal**: Kubernetes probes can detect service health.

**D.1 PostgREST Health Probe**
1. Configure Kubernetes liveness/readiness probes in `postgrest/deployment.yaml`:
   - Use TCP socket probe on port 3000 (already done per recent commits)
   - Optionally add HTTP probe to `/health` endpoint once view exists

**D.2 Job Trigger Health Endpoint**
1. Verify FastAPI `/health` endpoint exists in job-trigger service
2. Configure probes in `job-trigger-deployment.yaml`

### Phase E: CI/CD Pipeline (P1 - GitHub #59)

**Goal**: Automated testing on PRs, image builds on merge.

**E.1 PR Testing Workflow**
1. Create `.github/workflows/ci.yaml`:
   - Trigger on pull_request to main/staging
   - Run `pytest tests/` with PostgreSQL service container
   - Run `ruff check .` for linting
   - Fail on test failures

**E.2 Build Pipeline Enhancement**
1. Update `.github/workflows/build-push.yaml`:
   - Add test step before build
   - Add image vulnerability scanning (optional)

### Phase F: Observability Integration (P2 - GitHub #11, #61)

**Goal**: Metrics and alerts flow to dk-alchemy observability stack.

**F.1 Enable ServiceMonitor**
1. Verify Prometheus Operator CRDs exist in cluster
2. Uncomment ServiceMonitor in `k8s/base/kustomization.yaml`
3. Update namespace selectors if needed

**F.2 CronJob Failure Alerts**
1. Update `k8s/base/alert-rules.yaml`:
   - Add alert for CronJob failures
   - Add alert for data staleness
2. Configure alert routing (if not already done)

### Phase G: Container Images (P1 - GitHub #54, #55)

**Goal**: All services have published container images.

**G.1 Verify Job Trigger Image**
1. Confirm `ghcr.io/data-kinetic-projects/dk-data-fe/job-trigger` is built and pushed
2. Verify image is pullable from cluster

**G.2 Ingestion CronJob Images**
1. Verify CronJobs reference correct images
2. If needed, create separate Dockerfile for ingestion jobs

## Risk Register

| Risk | Impact | Mitigation |
|------|--------|------------|
| JWT validation breaks existing clients | Service outage | Deploy to staging first; document migration path for clients |
| db-init changes break existing database | Data loss | Test in fresh database first; backup before deployment |
| Permission changes lock out users | Access denied | Test role queries before deployment; have rollback plan |
| CI pipeline slows development | Velocity impact | Keep pipeline under 10 minutes; parallelize tests |
| ServiceMonitor requires missing CRDs | Observability gaps | Verify CRDs exist before enabling; keep disabled if missing |
