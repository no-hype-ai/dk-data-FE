# Data Model: Platform Stabilization

**Feature Branch**: `010-platform-stabilization`
**Date**: 2026-02-14

## Overview

This feature is primarily infrastructure-focused. It does not introduce new application-level database schemas. However, it introduces backup metadata tracking and modifies existing configuration entities.

## Entity: Backup Snapshot (New — Operational)

Represents a point-in-time database backup stored in MinIO.

| Attribute | Type | Description |
|-----------|------|-------------|
| filename | string | Unique identifier, format: `dk_data_{timestamp}_{type}.dump` |
| type | enum | `daily` or `weekly` |
| namespace | string | Source namespace (`dk-data-staging` or `dk-data-prod`) |
| timestamp | datetime | Backup creation time (UTC) |
| size_bytes | integer | Backup file size |
| checksum | string | SHA256 hash of the backup file |
| object_count | integer | Number of database objects (from `pg_restore --list`) |
| storage_path | string | Full MinIO path: `postgres-backups/{namespace}/{type}/{filename}` |
| retention_days | integer | 7 for daily, 30 for weekly |

**Lifecycle**: Created → Verified → Retained → Expired (auto-deleted)

**Storage**: MinIO object metadata (tags), not database tables. No new SQL schema required.

## Entity: Platform Secret (Modified — Configuration)

Existing Doppler-managed secrets extended with GHCR credentials.

| Secret Key | Environment | Purpose |
|------------|-------------|---------|
| POSTGRES_HOST | all | Database hostname |
| POSTGRES_PORT | all | Database port |
| POSTGRES_USER | all | Database username |
| POSTGRES_PASSWORD | all | Database password |
| POSTGRES_DB | all | Database name (standardized to `dk_data`) |
| JWT_SECRET | staging, prod | PostgREST JWT validation secret |
| POSTGREST_PASSWORD | all | PostgREST authenticator role password |
| **GHCR_USERNAME** | staging, prod | **New**: GitHub Container Registry username |
| **GHCR_PASSWORD** | staging, prod | **New**: GitHub Container Registry PAT |
| **MINIO_ACCESS_KEY** | staging, prod | **New**: MinIO backup user access key |
| **MINIO_SECRET_KEY** | staging, prod | **New**: MinIO backup user secret key |

## Entity: Scheduled Job (Existing — No Changes)

CronJobs are defined in Kubernetes manifests. No data model changes, but CronJob configurations gain:
- Explicit `backoffLimit: 2` for retry logic
- Adjusted `activeDeadlineSeconds` per job type (1h for daily, 2h for weekly)

## Entity: Coverage Report (New — CI Artifact)

Generated by pytest-cov in GitHub Actions. Not stored in database.

| Attribute | Type | Description |
|-----------|------|-------------|
| format | string | `xml` (Cobertura), `html`, `term-missing` |
| coverage_percent | float | Aggregate line+branch coverage |
| fail_threshold | float | Minimum coverage to pass CI (starts at 15%) |
| generated_at | datetime | CI run timestamp |
| commit_sha | string | Git commit that produced this report |

**Storage**: GitHub Actions artifacts (coverage.xml, htmlcov/). PR comments via MishaKav/pytest-coverage-comment action.

## Configuration Changes (Not Entities)

### Database Name Standardization

| File | Before | After |
|------|--------|-------|
| `docker-compose.yml` | `POSTGRES_DB: "${POSTGRES_DB:-edwards_tavr}"` | `POSTGRES_DB: "${POSTGRES_DB:-dk_data}"` |
| `init_database.sql` | `\connect edwards_tavr` | Removed (caller specifies) |
| `.github/workflows/ci.yaml` | `POSTGRES_DB: dk_data_test` | `POSTGRES_DB: dk_data_test` (no change, test DB is separate) |
| K8s (Doppler) | `dk_data` | `dk_data` (no change) |

### Kustomize Image Management

| File | Before | After |
|------|--------|-------|
| `k8s/base/ingestion/job-trigger-deployment.yaml` | `image: ghcr.io/.../job-trigger:main-5f46ed1` | `image: ghcr.io/.../job-trigger:latest` (placeholder) |
| `k8s/overlays/staging/kustomization.yaml` | No `images:` field | `images: [{name: ..., newTag: staging-<sha>}]` |
| `k8s/overlays/prod/kustomization.yaml` | No `images:` field | `images: [{name: ..., newTag: prod-<sha>}]` |

### Network Policy Extension

Add MinIO egress rule to `dk-data-egress` NetworkPolicy:
- Destination: `infra` namespace, port 9000/TCP
- Purpose: Allow backup CronJobs to write to MinIO
